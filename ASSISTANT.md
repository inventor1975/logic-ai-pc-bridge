# Как ассистент (ИИ) пользуется мостом

Мост держит токен и делает I/O; ассистент только **читает файлы и пишет
файлы**. Ошибся — ошибся в файле, а не в чужом чате. Этот файл — операционный
контракт для ЛЮБОГО ИИ, что водит бота (не про права — права в `PROTOCOL.md`).

Всё промерено болью 2026-08-22; грабли помечены ⚠.

## 1. Входящее: что тебе адресовали

    requests/<mid>-<chat>.json     сообщения, начатые с имени ассистента
    tg_log.jsonl                   ВЕСЬ разрешённый чат (контекст)

Мост сам ставит 👀 на адресованное — «принято, будет отвечено». Это обещание;
исполнить его — твоя работа.

## 2. Ответить словами

    outbox/<любое-имя>.json
    {"chat_id": N, "text": "...",
     "answers": ["<mid>-<chat>"],     // ЧТО закрываем — см. §4
     "done_emoji": "👍"}              // необязательно; дефолт 👍

Мост отправит текст, уберёт заявку(и) из `answers` в `served/` и СМЕНИТ 👀 на
`done_emoji`. Без `answers` глаз остаётся 👀 и заявка копится → ложные
«НЕКОМУ ВЗЯТЬ». ⚠ **Всегда называй заявку, на которую отвечаешь.**

## 3. Послать файл

    {"chat_id": N, "file": "/абсолютный/путь", "text": "подпись"}

⚠ Ключ **file**, не `path`; подпись — **text**, не `caption`. Неверный ключ
роняет сообщение МОЛЧА (ни в sent/, ни в лог). Арбитр доставки файла — строка
в `sent_by_rule.log`.

## 4. Закрыть глаз (👀 → готово)

Глаз — это РЕАКЦИЯ на сообщении. Закрыть = СМЕНИТЬ реакцию, не слать лайк
рядом. Два пути:

    в ответе:  поле "answers": ["<mid>-<chat>"]      (см. §2)
    меткой:    outbox/<mid>-<chat>.react.json
               {"chat_id": N, "message_id": M, "emoji": "👍"}

⚠⚠ **Эмодзи должен быть из набора реакций Телеграма** (`config.VALID_REACTIONS`).
`✅ ❌ 🟢 ✔` и большинство прочих — НЕ реакции. Невалидный эмодзи мост теперь
отвергает громко (`REACTION_INVALID` в логе). До 2026-08-22 он срывался в
отправку эмодзи ОТДЕЛЬНЫМ сообщением — так ушло ~20 «✅», а глаза не сменились.
Для «готово» бери **👍**. Снять глаз совсем: `*.unreact.json` (пустая реакция).

Арбитр: `mark 👍 -> chat/mid: reaction` (хорошо) против `: message` (сорвалось).

## 5. Напоминания

    reminders/<имя>.json
    {"at": "2026-08-22T17:00:00+00:00", "chat_id": N, "text": "...",
     "ack": true, "every_min": 5, "max_tries": 24}   // ack-поля необязательны

`at` — точный UTC (разбор человеческого времени — твоя работа, не моста).
С `"ack": true` мост шлёт снова каждые `every_min` минут, ПОКА не отреагируют
(любой значок = «видел»), либо пока не упрётся в `max_tries` (тогда сдаётся
вслух). Без `ack` — один раз. Отмена: реакция куратора, либо убрать файл.

## 6. Проверять доставку — не по отсутствию строки

    текст ушёл  → файл в sent/
    файл ушёл   → строка в sent_by_rule.log
    метка ушла  → `mark ... reaction` в bridge.out

⚠ Диагноз по ОТСУТСТВУЮЩЕЙ строке лога обманывает: молчание бывает и когда
сообщение проглочено схемой. Смотри в точку назначения, а не на её след.

## 7. Чего НЕ делать
- Не оставлять заявку без `answers` (глаза копятся).
- Не ставить невалидную реакцию (см. §4).
- Не править ЖИВОЕ дерево `LogicBridge/`; работа на клоне, выкат — отдельным
  решением куратора, со сверкой отпечатков и `drift.py --approve` после.

## 8. Контрольные вопросы (против потери контекста ассистента)

Каждое 5-е адресованное сообщение принципала мост роняет ОТДЕЛЬНУЮ заявку
`control-<mid>-<chat>.json` (сторож объявит её как «ТЕБЯ ЗОВУТ» — не пропустишь).
Её текст — от `selfcheck present`: сперва РАСКРЫТИЕ правды по твоему прошлому
ответу (из кода, не из твоего чутья), затем НОВЫЙ вопрос. Пишется ПОСЛЕ заявки
человека, так что самопроверка не задерживает его сообщение. На control-заявку
глаз не ставится и nudge её не трогает — она не человеческая.

    видишь control_question -> отвечай на новый:
        ./selfcheck.py commit "твой ответ"
    правду по нему узнаешь на СЛЕДУЮЩЕМ контрольном (отвечаешь ДО раскрытия —
    списать нельзя). Промахнулся -> идёшь и перечитываешь то, что он назвал.

Судья — код (ztl.py), не ассистент: сползший ты себя не пропустит.
Инструмент: `Projects/SelfCheck/` (cards.json, selfcheck.py).

Безопасность триггера (по фэн-шую): команда — ФИКСИРОВАННЫЙ список
(`config.SELFCHECK_PRESENT`), без `shell=True`, без пользовательского ввода ->
инъекции нет. Секретов не требует (токен не передаётся). Осечка/таймаут (8с) ->
поле просто не появляется, доставка НЕ страдает. Единственная оговорка: запуск
синхронный, так что зависший selfcheck задержит одно сообщение до 8с (fail-safe).
